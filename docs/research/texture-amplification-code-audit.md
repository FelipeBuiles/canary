# Texture amplification: code audit

Reviewed: 2026-09-19. **Historical audit of the pre-hardening code; remaining recommendations are proposed.** This is a local-source audit, supplementing [the earlier investigation](image-texture-fidelity.md). The subsequent [project inspection and implementation note](dunwich-texture-propagation.md) records changes addressing the authority wording, hybrid Draw scope and calibration prompt. This audit does not establish visual causation, provider behavior, or successful mitigation. No image generation was requested.

## Existing protection

- The shared [surface-fidelity policy](../../novel_to_comic/src/novel_to_comic/rendering_fidelity.py) explicitly addresses cellular mottling, worm-like patches, uniform speckles, material specificity, detail hierarchy and reference-defect amplification. It preserves deliberate artistic texture and limits edit cleanup to authorized changes. Adding another generic negative prompt would duplicate existing work.
- [Asset compilation](../../novel_to_comic/src/novel_to_comic/generation_prompt.py) injects that policy into Style/Cast constraints; [hybrid Draw style projection](../../novel_to_comic/src/novel_to_comic/style_contract.py) injects it before request freezing. [Integration tests](../../novel_to_comic/tests/test_rendering_fidelity_compilation.py) cover prompt hashes, reference/profile invariance and correction lineage. These checks establish wiring, not image quality.
- [Cast reference compilation](../../novel_to_comic/src/novel_to_comic/compiled_request.py) restricts character references to approved identity/state facets and expressly ignores their paper texture, medium and rendering density. [Reference sheet packing](../../novel_to_comic/src/novel_to_comic/reference_sheets.py) retains source pixels without resizing/cropping and rejects excess capacity.

## Concrete gaps

1. **The authority language competes with the fidelity policy.** `compile_reference_instruction()` calls the approved image the “sole visual rendering style authority” and says to match its *exact* mark-making, wash density and rendering density. `_build_sections()` says that image overrides any conflicting textual style notes. Neither local instruction distinguishes intended medium from incidental artifacts; that distinction appears separately in generic constraints. This is a plausible instruction-level amplification risk, not evidence of a model-internal cause. [Source](../../novel_to_comic/src/novel_to_comic/compiled_request.py)
2. **Hybrid Draw has a weaker separation between design and rendering authority.** Its `reference_scope` preserves subject/state design, but does not repeat the Cast compiler's explicit instruction against inheriting reference medium, paper texture and rendering density. The policy identifies style proofs as rendering-only authority, yet does not state as clearly that character and location assets cannot contribute an extra texture layer. [Source](../../novel_to_comic/src/novel_to_comic/page_drawing.py)
3. **Calibration creates another generative hop.** `_generate_character_style_board()` renders material/mark studies from the approved proof; `_character_style_reference()` uses the board when its producing request matches. That check establishes freshness, not surface quality. The board then becomes rendering evidence for character generation. The abstraction solves recognizable-identity leakage, but provides a plausible second opportunity to intensify a noisy proof before producing identity assets. [Source](../../novel_to_comic/src/novel_to_comic/stages/s3_cast.py)
4. **Visual review has no explicit surface-fidelity category.** `VisualFinding.category` allows identity, appearance, prop, scene and composition. The prompt checks those concerns and says not to judge style preferences. It does not explicitly compare unwanted texture contrast/scale across unrelated surfaces against selected artistic intent. A clean review cannot be interpreted as texture acceptance. [Source](../../novel_to_comic/src/novel_to_comic/page_visual_review.py)
5. **Legacy comments describe protections that are not active.** `RefStrategy.use_style_sample_refs()` and `use_location_plate_refs()` describe omitting GPT Image 2 references to avoid artifacts, but repository source searches find no callers. `cast_style_ref()` returns the chosen style on every model route. `_generate_prop_refs()` still claims GPT Image 2 props are text-only, despite calling the same style-reference compiler. Do not cite those comments as an existing mitigation or revive automatic reference dropping. [Strategy source](../../novel_to_comic/src/novel_to_comic/image_ref_strategy.py), [Cast source](../../novel_to_comic/src/novel_to_comic/stages/s3_cast.py)

## Recommended sequence

1. **Inspect provenance before editing prompts.** For this project, check the exact frozen Style, calibration, Cast and Draw prompts for the current fidelity sentences. Compare the original proof, board, reference assets and page crops at native resolution and common reading size. If these assets predate the policy, that is different evidence from policy failure. Inspect explicit correction parents; the edits endpoint alone is not an edit chain.
2. **Remove local ambiguity in authority wording.** Retain the approved proof's intended medium, palette, contour language, abstraction and material behavior; explicitly subordinate incidental texture noise to the shared fidelity policy in the same style-reference instruction. Preserve all selected anchors and artistic texture. Use one canonical shared clause instead of accumulating competing prompt blocks.
3. **Bring Draw reference scopes to parity.** State that subject assets own identity/state and location assets own geometry/material identity, while the selected style owns rendering. Explicitly prohibit copying incidental surface defects or adding grain from each reference. Do not omit identity references or treat required materials as irrelevant.
4. **Make the upstream review actionable.** Add an explicit human-visible surface-fidelity rubric for the approved proof and calibration board before downstream spend. A future automated visual review should report observable cross-material mottling, contour loss, and deviation from intended texture separately from aesthetic preferences; it must retain uncertainty and require visual evidence. Persist any accepted clean authority as a new revision.
5. **Evaluate, then claim efficacy.** Provider-free tests should cover conflicting authority prose, shared policy inclusion, source invariance and fixed profiles. A separately authorized visual experiment should hold model, dimensions, quality and reference bytes fixed while changing only authority wording; test a clean-approved-source condition separately. Do not silently denoise references, globally smooth pages, change edition profiles, or auto-retry paid generations.

No implementation changes were made by this audit. Existing rendered pages are not repaired by changed compiler wording.

## Official documentation cross-check

Verified against the fetched [OpenAI image prompting guide](https://developers.openai.com/api/docs/guides/image-prompting#prompting-fundamentals): assign each numbered reference a purpose, describe how inputs combine, separate requested edits from preserved details, and inspect each iteration. These support explicit per-reference authority rather than an undifferentiated instruction to copy a reference's exact rendering.

OpenAI warns that repeated edits can alter protected details and recommends evaluating full edit sequences. Prompting alone does not guarantee unchanged pixels. This supports conservative correction scope and inspection; it does **not** establish the cause of this project's blotches or prove our proposed clause effective. [Editing and evaluation guidance](https://developers.openai.com/api/docs/guides/image-prompting#migrate-an-existing-workflow)

The same page's [GPT Image 2 reference](https://developers.openai.com/api/docs/guides/image-prompting?model=gpt-image-2#gpt-image-2-guide) links to these shared techniques while noting that illustrated examples use GPT Image 2.5 and results vary by model. Its API parameter table says GPT Image 2 always processes image inputs at high fidelity; lowering `input_fidelity` is therefore not a documented mitigation. These API facts do not establish which backend model a particular Codex development route actually used.
