# Slice 10 Implementation Handoff

Date: 2026-07-12

## Contract delivered

- Added `FrozenGenerationRequest` and `FrozenReferenceSnapshot` in
  `novel_to_comic.frozen_requests`.
- Added versioned request values: discriminator
  `canary.frozen-request/1`, schema version `1`,
  `frozen-generation-request/1`, `frozen-reference-staging/1`, and
  `provider-wire/1`.
- Project-scoped storage is `<project>/requests/`: immutable
  `requests/<request_id>/manifest.json`, mutable lifecycle
  `requests/<request_id>/status.json`, and deduplicated real files at
  `requests/blobs/<sha256>`.
- `submit_frozen_request` reads each selected source once, verifies its
  expected digest, stages a write-once content-addressed copy, verifies it
  again, and atomically publishes a canonical manifest whose
  `manifest_sha256` covers the unsigned manifest. The portable wire stores
  only relative blob locators, so storage metadata does not change the
  execution fingerprint.
- `load_frozen_request` and `execute_frozen_request` revalidate the manifest,
  wire fingerprint, snapshot order/digests/lengths, and blob bytes immediately
  before transport. The queued runner consumes only the persisted request.
- Added `enqueue_frozen_generation_job` in `server.credited_job`: freezing
  happens before job publication, prompt/reference discovery is absent from
  the runner, and idempotent queued/concurrent/completed replays do not create
  another provider job or debit.
- Added `update_frozen_request_status` with result/provenance/job metadata and
  `gc_unreferenced_blobs`, which retains referenced blobs and removes only
  unreferenced independent regular files.
- Request-store locking, request/blob reads, publication, status updates, and
  GC retain already-open no-follow descriptors through their critical
  sections. Source/blob/reference materialization rejects symlinks and hard
  links and reads from the verified inode. Queued output finalization also
  uses no-follow descriptor-relative atomic writes and enforces project scope.
