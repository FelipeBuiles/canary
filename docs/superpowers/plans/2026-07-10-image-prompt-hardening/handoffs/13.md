## Contract delivered

- Added `GET /api/projects/{project_id}/generation-requests/preview` for a
  deterministic, no-model-call draft projection. It returns `Draft projection`,
  `exact: false`, and `exactness: non-exact` until a matching frozen request is
  supplied.
- Added `POST /api/projects/{project_id}/generation-requests/prepare` for an
  explicit, no-image-call preparation action. It freezes the request with
  status `prepared`, returns its request id/fingerprint, and discloses estimated
  cost/credits without reserving or charging credits.
- Added `GET /api/projects/{project_id}/generation-requests/{request_id}`.
  Project resolution/authentication remains owned by `get_project`; request
  IDs are loaded only from that authorized project directory. Default responses
  expose only state/exactness/warnings. `dev_content=1` exposes the persisted
  semantic context, portable provider wire, ordered refs/digests/instructions,
  dropped refs, geometry, controls, versions, hashes, and redaction-safe
  provenance.
- Extended frozen request manifests with optional `request_context` and
  prepared/invalidated lifecycle statuses. The exact Dev Content wire is
  reconstructed from the frozen portable manifest representation, not from
  separate frontend fields. Absolute transport paths, credentials, signed URLs,
  and provenance path/locator fields are not returned.
- Added `invalidate_prepared_requests`. Authoritative panel prompt edits mark
  matching prepared requests invalidated; generation rejects invalidated
  requests. A prepared request supplied to panel regeneration is validated by
  deterministic fingerprint comparison and consumed by the existing frozen-job
  path without hydrating or calling the prompt model again.
- Added `generation_request_preview.py` and frontend API/query support. Panel
  Dev Content shows the state label, exactness, prepare action, accounting
  disclosure, semantic prompt, provider wire, refs/dropped refs, geometry,
  controls, and completed provenance. The default prompt display is explicitly
  labeled `DRAFT PROMPT PROJECTION` / `DRAFT ASSEMBLED PROMPT`.
- Preview/provenance schema values remain aligned with the existing compiled,
  provider-wire, frozen-request, and common image-provenance versions; the new
  preview projection uses schema version `1`.

## Behavior and deliberate deviations

- The exact preview slice is panel-focused because the current interactive
  editing surface and generation submission path are panel-specific. Non-panel
  callers persist the same semantic context and frozen wire contract for the
  read/projection layer to consume in later integration work.
- Preparation is deterministic and free: it does not invoke the prompt model,
  image provider, credit reservation, or debit. The disclosed estimate is for
  explicit image submission.
- A prepared request is transitioned to `queued` by the existing frozen-job
  enqueue path only after credit checks succeed. If submission is rejected, it
  remains prepared.
- Frontend repository lint remains non-green because of pre-existing unrelated
  errors in other components/tests and existing React effect rules. No new
  lint error was reported for the new API/type code; TypeScript/build passed.
- No backend stage boundaries or provider semantics changed. No paid/model
  calls were made.
