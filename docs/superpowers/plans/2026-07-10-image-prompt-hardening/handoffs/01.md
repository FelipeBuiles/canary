# Slice 01 Implementation Handoff

Date: 2026-07-10
Status: COMPLETE

## Contract delivered

### Patch contract

Manual prompt edits now use an explicit patch contract. The PUT
`/prompts/{scene_id}/{panel_number}` endpoint requires body
`{"fields": {<authoritative field>: <value>, ...}}` and no longer trusts a full
client-supplied `ImagePrompt` as authoritative state.

- `novel_to_comic.panel_store.AUTHORITATIVE_PROMPT_FIELDS` — frozenset of the
  only fields a manual edit may set: `composition`, `setting`, `lighting`,
  `mood`, `constraints`, `continuity_note`, `props`, `key_objects`,
  `visual_requirements`.
- `novel_to_comic.panel_store.APPLY_PROMPT_PATCH_FORBIDDEN_KEYS` — frozenset of
  derived/protected fields a client may never set through the patch contract:
  `full_prompt`, `distilled_prompt`, `visual_brief`, `reference_image_paths`,
  `style`, `prompt_version`, `planned_panel_id`, `scene_id`, `panel_number`,
  `width`, `height`, `steps`, `has_narration_caption`, `narration_mode`,
  `preferred_caption_zone`, `location_state_id`, `generation_*`, `crop_policy`,
  `transition_in`, `transition_out`.
- `novel_to_comic.panel_store.apply_prompt_patch(prompt, patch) -> ImagePrompt`
  — the single owner of manual-edit application and derived-field invalidation.
  Returns a new model; input is not mutated.

### Authoritative field set

Authoritative (editable): scene direction (`composition`, `setting`,
`lighting`, `mood`), subject action/expression/position (via `subjects`),
user constraint addenda (`constraints`, `continuity_note`), props/key-objects/
visual-requirements, and intentional manual layout edits (`layout`).

Excluded (protected/derived): anchors (`subjects[].identity`,
`appearance_locked`, `appearance_guard`, `character_id`, `name`), reference
paths, system constraints/immutables, visual briefs, distilled prompts, and
rendered prompt strings. Subject patches that carry an identity/anchor key are
rejected by `_coerce_subjects`.

### Invalidation rules (centralized in `apply_prompt_patch`)

- Any semantic field change (incl. `subjects`) → clear `visual_brief` AND
  `layout`, then re-derive `full_prompt` and `distilled_prompt`.
- A `layout`-only change → preserve the supplied layout and leave
  `visual_brief` intact.
- `full_prompt` is always re-derived from structured fields; `distilled_prompt`
  is regenerated deterministically.

### Instructed-edit invalidation (prompt_instructions)

`apply_instruction_patch` now clears `layout` in addition to `distilled_prompt`
and `visual_brief` (previously cleared only the two prompt bodies). The draw
path rehydrates all three via `ensure_distilled_prompt` / `ensure_visual_brief`
/ `ensure_layout` before generation — unchanged.

### Frontend

- `updatePrompt` API sends `{fields: Partial<ImagePrompt>}` (was: full
  `ImagePrompt`). `useUpdatePrompt` signature is now `{project, sceneId,
  panelNumber, fields}`.
- The "ASSEMBLED PROMPT" section is read-only in both `PromptLineageCard`
  (PanelDetailModal path) and `DirectRoom` (DirectPromptDetail path). Raw
  `full_prompt` editing is no longer presented as authoritative.
- `PanelDetailModal` computes a diff of only changed authoritative fields via
  `diffAuthoritativeFields` before sending.
- `DirectRoom.saveStructuredPatch` no longer appends `full_prompt` to the
  outgoing patch.

## Behavior and deliberate deviations

- The PUT endpoint body contract is a breaking change: callers must send
  `{"fields": {...}}` instead of a full `ImagePrompt`. This is acceptable per
  the plan ("breaking internal prompt JSON/model changes are acceptable").
- `save_prompt` (the persistence step) is unchanged — it still re-derives
  `full_prompt` and `distilled_prompt` defensively. The patch contract calls
  `apply_prompt_patch` first, then `save_prompt` to persist.
- Identity anchors (`subjects[].identity`, `appearance_locked`,
`appearance_guard`, `character_id`, `name`) are rejected in the dict (wire)
  path of `_coerce_subjects`. Internal `PromptSubject` instances are deep-copied
  without re-validation (trusted path); the JSON API is the security boundary.
- No visual-brief or layout content was redesigned; the draw/rerender
  hydration path (`ensure_visual_brief` / `ensure_layout`) is unchanged.
- No schema or version value changed. No paid/model calls were made.

## Independent review

- Verifier result: CONFIRMED (after one resolved finding).
- The verifier initially REFUTED claim 8 ("ASSEMBLED PROMPT read-only") for the
  `DirectRoom` path: `DirectRoom.tsx` still exposed an editable ASSEMBLED
  PROMPT and its `saveStructuredPatch` appended the forbidden `full_prompt`
  key, which would have caused all DirectRoom structured edits to be rejected
  by the server with 400. Both issues were fixed: the section is now read-only
  and `saveStructuredPatch` sends only authoritative fields. The verifier also
  noted a minor theoretical gap in the `_coerce_subjects` model-instance
  branch; this was assessed and left as-is (internal trusted path; the JSON
  wire path is the security boundary and is covered by tests).
- Security review: not required; no auth, secrets, signed assets, storage
  permissions, command execution, or untrusted provider-data behavior changed.
  The patch contract does harden the prompt-edit endpoint against
  attacker-controlled derived/reference data (rejected via `ValueError` → 400).
