## Contract delivered

### Prompt hygiene, budgets, and geometry truth

The compiled request (`compiled_request.compile_generation_request`) now
produces compact, non-duplicative, text-safe, budget-aware prompts that are
truthful about requested geometry and supported controls. No reference
selection, order, or authority is changed from Slice 04.

`COMPILED_REQUEST_SCHEMA_VERSION` remains `1` (Slice 06 is additive: it adds
hygiene fields and verification, not new stored shape fields).

#### Prompt-section priority / budget rules

Section-aware budgeting (`prompt_hygiene.apply_prompt_budget`):

- **Non-truncatable sections** (`_NON_TRUNCATABLE_SECTIONS`):
  `protected_anchors`, `reference_instructions`, `system_constraints`.
  These reach the provider intact — a provider-side prefix slice that discards
  them is a correctness bug.
- **Compressible sections** (dropped lowest-priority-first):
  `scene_direction` (editable scene prose) is dropped before `user_addenda`
  (authored corrections).
- **Impossible request fails explicitly**: when protected material alone
  exceeds the route's `prompt_char_limit`, the compiler raises
  `CompiledRequestError("...character budget...")` — no provider may
  prefix-slice protected material later.
- **No budget when `prompt_char_limit is None`**: routes without a verified
  provider-side prefix slice (Gemini, GPT Image 2, Unknown) never fail on
  protected length.

#### Text diagnostics

- `sanitize_dynamic_text(value)` removes readable-text cues from editable/
  dynamic scene fields: composition, setting, lighting, mood, props, key
  objects, visual requirements, continuity, user addenda, and the visual
  brief. It strips "reading/saying/labelled X" clauses from physical
  text-bearing objects (the physical object survives; the requested readable
  content does not), strips bare text-render phrase fragments, and drops
  sentences that are purely text-render instructions.
- **Protected anchors are NEVER sanitized** — they are emitted with `.strip()`
  only.
- `detect_anchor_text_conflicts(prompt)` returns `AnchorTextConflict`
  diagnostics when a protected anchor itself requests readable text. The
  anchor is preserved verbatim; the compiler appends an
  `anchor_text_conflict: ...` warning (non-blocking); the generated
  no-lettering constraint is retained. These warnings are EXCLUDED from
  `compiled_request_sha256` (diagnostics must not affect provider identity).

#### Single-owner rules

- Each fact has one owner. The visual brief is deduplicated against the
  continuity note (`dedupe_brief_against_continuity`) — sentences whose
  significant tokens are fully covered by the continuity note are stripped.
- `visual_requirements` are normalized and semantically deduplicated
  (`dedupe_visual_requirements`): a requirement is dropped only when ALL its
  significant tokens are already owned by subject action/expression/position,
  key objects, props, or setting. A partial overlap (new token) is kept. The
  must-show list is capped at `_MUST_SHOW_MAX = 4` (the planner's intended
  1–4 details).
- Hardcoded medium directives (`strip_hardcoded_mediums`): unconditional
  "Use broad opaque gouache/oil/acrylic... color blocks" sentences are
  stripped from scene-direction prose. Medium guidance derives from the
  active selected style and appears once (in the `style` section).

#### Model capability fields (ImageModelProfile extension)

`ImageModelProfile` now carries:

- `prompt_char_limit: int | None` — verified character budget. REVE = 4000
  (matches `reve_layout._INSTRUCTION_MAX_CHARS`); GEMINI_FLASH_LITE /
  GPT_IMAGE_2 / UNKNOWN = None (no provider-side prefix slice).
- `native_aspect_modes: tuple[str, ...]` — the route's dedicated aspect
  parameter vocabulary. REVE = `("1:1","3:2","2:3","4:3","3:4","16:9","9:16")`;
  others = `()` (derive aspect from width/height only).
- `supported_controls: frozenset[str]` — the verified subset of generation
  controls the route actually forwards. REVE = `frozenset()`; GEMINI_FLASH_LITE
  / GPT_IMAGE_2 = `frozenset({"quality"})` (litellm_http forwards
  `config.image_quality`); UNKNOWN = `frozenset()`.
- `supports_control(name)` and `native_aspect_for(aspect_ratio)` helpers.

The compiler rejects phantom controls (`_validate_control_support`): a
`GenerationControls` with an unsupported field (e.g. `negative_prompt` on
Reve) raises `CompiledRequestError` before transport.

#### Native-aspect mapping

`_native_aspect_for` resolves the structural native aspect mode from the
prompt's effective aspect ratio + route profile. When the route has native
modes (Reve), a `Native aspect: <mode>` line is emitted in the geometry
section. When the route has no modes (Gemini), no native aspect line appears.
The prose aspect cue is emitted by the canonical compiler (visible in the
request), never added later by a handler.

#### Effective-dimension contract

- `requested_shape` + `effective_dimensions` are recorded in the pre-transport
  request (unchanged from Slice 05). Actual returned image dimensions belong
  only in result provenance.
- `panel_aspect.style_proof_dimensions()` → `(819, 1024)` (4:5 portrait,
  matching the style-sample prompt's "Portrait 4:5 frame" promise).
- `panel_aspect.location_plate_dimensions()` → `(1344, 768)` (landscape,
  matching the location-plate prompt's "clean wide environment design plate"
  promise).
- `panel_aspect.aspect_matches_shape(ratio, shape)` validates numerically —
  3:2 (1.5) and 16:9 (1.78) are both confirmed as landscape by coarse shape +
  numeric band; square and portrait are rejected.

## Behavior and deliberate deviations

- The compiler remains additive: it does not change
  `COMPILED_REQUEST_SCHEMA_VERSION` (still 1) and does not alter the stored
  `ImagePrompt` model. Hygiene is a generation-time projection applied in the
  compiled request.
- `GenerationControls` is now verified against route support. A route that
  later gains a verified control (e.g. Reve adds seed support) needs only an
  update to `_SUPPORTED_CONTROLS` — the hash already covers control intent
  (Slice 05).
- The text sanitizer is deliberately conservative on physical text-bearing
  objects: a "neon sign reading OPEN" becomes "a neon sign" (physical object
  survives, readable content stripped). Pure text-render sentences are dropped.
- The sanitizer has minor regex edge cases for unusual phrasings (bare
  present-tense "spell", "monitor showing on-screen text") documented by the
  verifier; these do not affect the named adversarial cases in the brief.
- No paid/model calls were made.

### Post-verification corrections

A follow-up verification refuted the initial implementation on five integration
points. The following corrections are now part of the Slice 06 contract:

- Draw and estimate consume `CompiledGenerationRequest.final_prompt` directly;
  they no longer rebuild a parallel provider prompt from `ImagePrompt`.
- Draw submits and records `compiled.effective_dimensions`.
- Budgeting drops `scene_direction` before `user_addenda`, returns the retained
  section set, and fails on any residual over-budget request. Consequently,
  `final_prompt` is always the exact join of `sections`.
- `GenerationControls` includes `quality`; supported routes carry configured
  quality into the compiled request and hash, while unsupported routes omit it.
- Legacy prompts with only `full_prompt` retain that content through the same
  dynamic-text sanitizer as the final scene-direction fallback.

Regression coverage is in `test_prompt_hygiene_geometry.py` and
`test_image_failure_meta.py`. No paid/model calls were made.

Fresh post-correction verifier result: **CONFIRMED**. It independently checked
draw/estimate compiled-prompt consumption, effective dimensions, residual
overflow rejection, compression order, section/final-prompt consistency,
quality control identity, and the sanitized `full_prompt` fallback. Its focused
suite passed 100 tests. The only non-blocking observation was that quality
values remain strings rather than a closed enum; route-capability validation is
enforced as required by this slice.
