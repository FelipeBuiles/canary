## Contract delivered

### Model capability profile

`image_models.ImageModelProfile` is the immutable route-level reference
capability seam. `image_model_profile(model)` and
`image_model_profile_for_config(config)` resolve it from Slice 00's truthful
`ImageRoute`:

| Route | Hard application cap | Supported roles |
|---|---:|---|
| `REVE` | 4 | subject, prop, continuity, style, location_plate |
| `GEMINI_FLASH_LITE` | 10 | subject, prop, continuity, style, location_plate |
| `GPT_IMAGE_2` | 4 | subject, prop |
| `UNKNOWN` | 10 | subject, prop, continuity, style, location_plate |

Prompt-length, aspect, and generation-control capabilities remain deferred.

### ReferencePlan API

`image_references.py` is the single panel-reference selection owner:

- `build_reference_plan(...) -> ReferencePlan`
- `ReferencePlan(expected_route, selected, dropped,
  selection_fingerprint, warnings)`
- `ReferenceAsset` records path, role, entity/state ids, authority scope,
  preserve/ignore facets, pose, selected content SHA-256, lineage parent hash,
  and label.
- `DroppedReference` records a semantic candidate/asset, `DropReason`, and
  actionable detail.
- `ReferenceMaterializationError` stops generation when a finalized candidate
  cannot be read.
- `ReferencePlan.to_ref_images()` is the sole projection to provider `RefImage`
  objects and preserves final order.

Required drop reasons exist: `missing`, `unreadable`, `duplicate_entity`,
`provider_cap`, `unsupported_role`, `state_conflict`, `stale_lineage`,
`unverified_lineage`, and `lower_priority`. Absent lineage is currently a
non-blocking warning rather than a drop; Slice 08 will make lineage mandatory.

### Candidate resolution and slot policy

- Candidates resolve at draw/estimate time from `PromptSubject.character_id`,
  active appearance state ids, protected prop anchors, active location ids and
  states, primary-pose selection, current files, and current metadata.
- `ImagePrompt.reference_image_paths` was removed. Prompt version is now 23.
- One crop per visible character is selected. An explicit primary pose wins in
  canonical and state directories. Otherwise close shots prefer `front`, wide
  shots prefer `gesture`, and medium/default shots prefer `three_quarter`.
- GPT Image 2 defaults to a front-facing subject crop. When subject refs exist,
  prop images remain text-only and are diagnosed as lower priority.
- Subjects claim slots first, in panel order. With 0–4 subjects, every readable
  subject fits Reve's four slots; remaining slots use contextual policy. With
  more subjects than the route cap, overflow subjects remain in prompt text and
  are named in `provider_cap` diagnostics.
- Missing base references are named in `missing` diagnostics. Missing
  significant-state refs remain text-only and are diagnosed `state_conflict`.
- Contextual selection priority is deterministic and shot-aware: compatible
  continuity and close-detail critical props are strongest; an active
  location-state plate outranks redundant style; explicit critical props
  (named in key objects or visual requirements) outrank noncritical props;
  style is last.
- Final upload order is stable: subjects, props, continuity, style, location.
  Selection priority chooses what fits; final role order owns prompt indices and
  provider bytes.

### State authority and lineage

- Base look: canonical crop with `FULL_APPEARANCE` authority.
- Minor text-only state: canonical crop with `IDENTITY_ONLY`; preserve
  `face`, `hair`, `build`; ignore `wardrobe`, `anatomy`.
- Significant state with a dedicated state crop: `FULL_APPEARANCE` authority.
- Significant state without a dedicated crop: no contradictory canonical
  conditioning.
- `AppearanceState.canonical_equivalent` is an explicit opt-in for restored
  states that may safely use canonical full-appearance conditioning; it is
  propagated to `PromptSubject.appearance_state_canonical_equivalent` and the
  source projection. Equivalence is never inferred from an id or label.
- Character-state lineage reads the real state-sheet metadata sidecar (with a
  crop-sidecar fallback for fixtures) and compares `lineage_parent_sha256` with
  current canonical sheet bytes.
- Location-state lineage reads the state plate sidecar and compares it with the
  current canonical location plate. Mismatches are excluded as
  `stale_lineage`; missing metadata is selected under the documented
  `unverified_lineage` warning policy.
- Previous-panel continuity is enabled only by the previous prompt's match-cut
  transition and route/config policy. It is suppressed on any character-id set,
  character-state, or location-state change across the boundary.

### Fingerprint, cache, estimates, and diagnostics

`selection_fingerprint_hex()` hashes sorted JSON containing each selected
asset's final order, role, entity id, appearance state id, authority scope,
preserve facets, ignore facets, and content SHA-256. Paths and dropped/warning
diagnostics are excluded. Therefore selected-byte changes invalidate identity;
unselected diagnostic changes do not.

Panel generation metadata now persists the selection fingerprint and each
selected asset's content hash/semantic authority. Cache comparison includes
those selected fields while explicitly excluding `reference_diagnostics`.
Dropped references and warnings are logged at warning level and persisted in
generation metadata. Draw estimates and actual-run reservations build the same
final plan and use its selected count over the exact filtered prompt files,
including retry-failed panels.

Prompt rendering and the LiteLLM/Reve provider adapters consume finalized order
unchanged. The Reve adapter asserts the four-reference cap; both adapters raise
if finalized bytes become unreadable instead of silently dropping/reordering.

### Prior-slice repairs preserved

- Location anchors are no longer context-filtered; protected text remains
  byte-for-byte verbatim.
- Full serialized subject patches from the UI preserve matching protected
  fields, reject changed protected values, and edit only action/expression/
  position.
- `props`, `key_objects`, and `visual_requirements` are typed list overlays and
  survive canonical rebuilds.
- Only setting overlays bind to location state; framing, lighting, mood, and
  other state-neutral panel overlays survive location-state changes.
- Rebuilds re-render `full_prompt` and deterministic distilled prompt after
  overlay application.
