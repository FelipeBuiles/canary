# Slice 02 Implementation Handoff

Date: 2026-07-10
Status: COMPLETE

## Contract delivered

### Canonical prompt IR

The `ImagePrompt` now separates immutable source material (anchors) from
editable scene direction and generated system invariants. Three owners:

- **Protected anchors** — verbatim `visual_anchor` text from the Story Bible.
  Character anchors live on `subjects[].identity`; location and prop anchors
  live on the new `ImagePrompt.anchors` list.
- **Editable scene direction** — `composition`, `setting` (background only),
  `lighting`, `mood`, `key_objects`, `visual_requirements`, `props`, subject
  `action`/`expression`/`position`, `continuity_note`.
- **Generated system constraints** — count, one-body, single-instant,
  no-lettering, crop policy, appearance locks, unified canvas. Generated at
  render time by `generation_prompt.generate_system_constraints()`, never
  stored in `ImagePrompt.constraints`.

### New model: PromptAnchor

```python
class PromptAnchor(BaseModel):
    kind: Literal["character", "location", "prop"]
    entity_id: str
    name: str
    appearance_state_id: str | None = None
    text: str
```

Defined in `models/prompt.py`. Character anchors are NOT stored in this list —
they ride on `PromptSubject.identity` verbatim.

### New ImagePrompt fields

- `anchors: list[PromptAnchor]` — protected location/prop anchors (verbatim).
- `location_id: str | None` — the scene's location id.

### New PromptSubject field

- `appearance_state_id: str | None` — the active character appearance state id
  (None = base look). Set by the builder from the appearance resolver.

### Constraint split

- `ImagePrompt.constraints` is now **user addenda only** (None on a fresh
  build). It carries user-authored constraint notes (e.g. "non-graphic implied
  action"), nothing generated.
- System constraints are generated from typed fields by
  `generation_prompt.generate_system_constraints(prompt) -> list[str]` and
  emitted by `render_canonical_body(prompt) -> str`.
- Both manual edits (`apply_prompt_patch`) and instructed edits
  (`apply_instruction_patch`) can change user addenda but cannot remove system
  constraints — they are regenerated on every render.
- `_enforce_prompt_invariants` is now an intentional no-op (no-lettering is
  generated, not injected into `constraints`).

### Canonical renderer entry point

`novel_to_comic.generation_prompt.render_canonical_body(prompt) -> str`

Renders a deterministic prompt-body projection from owned sections:

1. Protected anchors (character identity + location/prop anchors) verbatim.
2. Scene direction (composition, setting, lighting, mood, props/objects,
   visual requirements, continuity).
3. System constraints (generated from typed fields).
4. User constraint addenda.

This is NOT the final provider-bound prompt — it lacks the finalized reference
selection and role instructions (deferred to Slice 05).

### Verbatim anchor resolution

`_character_identity(character, resolved)` in `prompting.py` returns exactly
one self-contained anchor:

- Base look → `character.visual_anchor` verbatim.
- Active state → `resolved.anchor` (the state's self-contained
  `visual_anchor`) verbatim.

Never concatenated with base + `default_outfit`, never passed through
`_shorten`/`_clean`/underscore replacement/translation/LLM. The old 120/180/220
character caps are gone for protected anchors.

### LLM visual-brief scope narrowed

`visual_brief_source_spec(prompt)` now emits ONLY scene direction: framing,
per-subject action/expression/position (NOT identity), setting (background),
lighting, mood, key objects, visual requirements, caption space, continuity,
and user constraint addenda. It does NOT emit:
- character identity/anchor text (protected)
- location anchor text (protected)
- system constraint text (generated)
- reference instructions (excluded)

For appearance-locked subjects it emits the lock status + continuity guard +
staging rule, but never the verbatim anchor text.

### Prompt version

`IMAGE_PROMPT_VERSION = 21` (was 20). Breaking stored prompt JSON is
acceptable per the plan.

### Panel-store forbidden keys extended

`APPLY_PROMPT_PATCH_FORBIDDEN_KEYS` now includes `anchors` and `location_id`
(protected canonical fields). `_coerce_subjects` rejects
`appearance_state_id` in wire-path subject patches.

## Behavior and deliberate deviations

- **Breaking stored prompt JSON**: `IMAGE_PROMPT_VERSION` bumped to 21. Old
  stored prompts will be rebuilt by `prompt_is_current` (version check). This
  is acceptable per the plan.
- **`full_prompt` no longer contains system constraints**: it renders only
  scene direction + user addenda + anchors. System constraints (count,
  one-body, etc.) appear only in `render_canonical_body` and
  `render_generation_prompt`. Tests that asserted on system constraints in
  `full_prompt` were updated to check the canonical body.
- **`setting` is background-only**: the location anchor moved to `anchors`.
  Existing tests that checked `prompt.setting` for location tokens were
  updated to check `prompt.anchors`. The `_filter_location_anchor_for_panel`
  interior/exterior filter still applies — it is a semantic correction
  (dropping outdoor tokens from an indoor panel's location anchor), not a
  mutation of the anchor's identity.
- **`props` display list simplified**: `props` on `ImagePrompt` now stores prop
  names only (was `f"{name}: {shortened_anchor}"`). The verbatim prop anchor
  text lives in `anchors`; the canonical projection emits it from there.
- **`render_generation_prompt` constraint section**: system constraints are now
  generated via `generate_system_constraints` and emitted as bullet lines;
  user addenda follow as separate bullets. The old `_LAYOUT_CONSTRAINT_LINE`
  constant was replaced by `_UNIFIED_CANVAS` in the generated system
  constraints (same text, new owner).
- No paid/model calls were made.
- No frontend files were touched (backend-only slice).
