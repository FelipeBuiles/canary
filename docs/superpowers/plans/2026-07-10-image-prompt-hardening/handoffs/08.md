# Slice 08 Implementation Handoff

Date: 2026-07-11

## Contract delivered

- `state_assets.STATE_ASSET_SPEC_VERSION = 1` and
  `StateAssetGenerationSpec` define character/location state generation:
  entity/state ids, exact active anchor, canonical parent identity/path/hash,
  preserved/overridden facets, style path/hash, configured route/model,
  effective shape/dimensions, state addendum/revision, rendered prompt, and
  lineage mode/status.
- State prompts are built directly from the exact state anchor. Character
  specs never inherit `default_outfit`; age, hair, anatomy, clothing, and
  incompatible gesture language are suppressed when overridden. Location
  specs let active damage, architecture, water level, weather, light, and
  atmosphere facets replace conflicting canonical clauses while retaining
  only non-conflicting landmark clauses.
- State corrections are independently stored at
  `refs/<char>/states/<state>/instructions.jsonl` and
  `plates/<loc>/states/<state>.instructions.jsonl`; canonical logs remain
  unchanged.
- State generation uses `_generate_state_asset_wire` for single and batch
  character/location paths: `compile_generation_request` →
  `compile_provider_wire_request` → `generate_wire_image`. The Slice 08 plan
  has an empty `ReferencePlan`, so it adds no canonical reference transport;
  state outputs record `lineage_mode=unconditioned` and
  `lineage_status=unverified` pending Slice 09 conditioning.
- Metadata schema includes asset/entity/state identity, exact state anchor,
  rendered-prompt hash/version, canonical/style paths and hashes, configured
  route/model, dimensions, addendum revision, lineage mode/status, facet
  decisions, and reserved generated-request/provenance links.
- `mark_dependent_states_stale` compares current canonical bytes with every
  dependent state parent hash, persists `lineage_status=stale`, and emits
  `state_asset_regeneration_required`. `revalidate_state_asset_lineage`
  prevents restored metadata from claiming false currency.
- Canonical character/location rerolls and restores invoke stale-lineage
  invalidation. Normal cast orchestration generates canonical character sheets
  before character states and canonical location plates before location states.
- Explicit character/location state routes cover regenerate, instructed
  regenerate, version list, restore, and metadata. Canonical location version
  list/restore parity was added. Existing auth, limiter, credited-job, and
  generation-job patterns are retained.
- Slice 04 lineage resolution recognizes the new canonical-parent field,
  explicitly excludes stale lineage, and applies the documented unverified
  policy to unconditioned/pre-contract outputs.

## Behavior and deliberate deviations

- State assets deliberately remain unconditioned in this slice. They traverse
  the shared compiled/wire seam with no selected references and are never
  represented as current/conditioned lineage. Slice 09 owns adding compatible
  canonical conditioning.
- Established location-state image paths (`plates/<state_id>.png`) remain
  unchanged because state ids are parent-prefixed and ReferencePlan consumes
  that contract. State instruction logs use a nested parent/state path.
- The resolver still reads the old `lineage_parent_sha256` field only to
  classify pre-contract metadata safely; new writes use
  `canonical_parent_sha256`.
- No frontend files or later-slice frozen/provenance contracts were added.
