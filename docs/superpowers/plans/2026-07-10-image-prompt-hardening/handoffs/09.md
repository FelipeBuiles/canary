# Slice 09 Implementation Handoff

Date: 2026-07-11
Status: COMPLETE

## Contract delivered

- `LineageMode.STATE_ONLY = "state_only"` joins `UNCONDITIONED` and `CONDITIONED`.
  A total transformation/destruction sets `state_only`: the canonical parent hash
  is retained as semantic lineage but not sent; the request generates from the
  self-contained state anchor.
- `build_state_reference_plan(spec, project_dir, *, route_profile=None)`
  → `ReferencePlan` is the single owner of state-asset reference selection. It
  reuses the Slice 04 `ReferencePlan` type and route caps:
  - **Character state**: the canonical character sheet is selected as a `subject`
    reference with `authority_scope=IDENTITY_ONLY`, `preserve_facets` over
    compatible identity (face/hair/build), and `ignore_facets` over every facet
    the active state overrides (anatomy/wardrobe/age/hair/face/build).
  - **Location state**: the canonical plate is selected as a `location_plate`
    with `preserve_facets` over architecture/landmarks/materials; the compiled
    instruction states the active damage/weather/time anchor wins.
  - Style is added as a `style` reference when the route cap has room; under a
    tight cap, identity is kept and style is dropped with a `PROVIDER_CAP` or
    `UNSUPPORTED_ROLE` diagnostic.
  - A total transformation (every identity facet replaced, or explicit identity
    negation like "no human face"/"transformed into a beast") or total location
  destruction (structure negation) omits the contradictory parent, records a
  `STATE_CONFLICT` drop, and sets `lineage_mode=state_only`.
  - Missing or digest-mismatched canonical parent raises
    `StateConditioningError` before any provider I/O — no silent fallback to an
    independent unconditioned image.
- `StateConditioningError(ValueError)` — structured failure for missing/stale
  canonical parents.
- Facet comparison uses clause-level text diff (`_changed_facets`) so a
  self-contained state anchor that *restates* unchanged identity (age, hair) is
  not falsely classified as an override. Keyword patterns extended with `face`
  and `build` facets plus `_TOTAL_IDENTITY_NEGATION` / structure-negation
  patterns for robust total-transformation detection.
- `StateAssetGenerationSpec` gained `reference_summary`, `compiled_request_sha256`,
  and `execution_fingerprint` fields. `build_state_reference_plan` and
  `_generate_state_asset_wire` populate them. `lineage_metadata()` now persists
  these plus the reference roles/hashes (deliverable 9).
- `revalidate_state_asset_lineage` now marks `CONDITIONED`/`STATE_ONLY` assets
  `CURRENT` when the parent hash matches (was: left unchanged); `UNCONDITIONED`
  remains `UNVERIFIED`.
- `_generate_state_asset_wire` in `s3_cast.py` builds a conditioned plan via
  `build_state_reference_plan` (was: empty plan). Signature accepts `project_dir`
  to locate the canonical parent. All four callers updated.
- All four state-asset generation paths (`regenerate_character_state_ref`,
  `regenerate_location_plate`, `_generate_character_state_refs._one_state`,
  `_generate_location_plates._one_plate`) capture `spec.lineage_metadata()`
  AFTER the wire mutates the spec, so persisted `.meta.json` records
  `conditioned`/`current` with populated reference summaries and request hashes.
  The cache-skip check in the two batch paths builds the plan before comparing.

## Behavior and deliberate deviations

- State assets are now **conditioned**, not unconditioned. The Slice 08
  `lineage_mode=unconditioned` / `lineage_status=unverified` baseline is
  superseded for newly generated state assets. Pre-existing (pre-Slice-09)
  metadata remains safely classified as `unconditioned`/`unverified` by the
  lineage resolver.
- The Slice 08 test `test_state_generation_uses_compiled_wire_without_canonical_reference`
  was renamed to `test_state_generation_uses_compiled_wire_with_canonical_conditioning`
  and updated to provide a canonical parent and assert a conditioned subject
  reference. The empty-ReferencePlan contract it documented was the Slice 08
  baseline, explicitly superseded by this slice.
- Total-transformation detection uses clause-level facet comparison plus
  identity-negation patterns. This is a heuristic, not semantic understanding —
  an unusual anchor that changes identity without triggering any facet keyword
  or negation pattern would still be conditioned. The brief frames this as
  acceptable because the `IDENTITY_ONLY` authority scope limits the damage (the
  canonical parent only conditions face/hair/build, and the active anchor is
  sent verbatim as the strongest signal).
- Canonical-first scheduling (canonical jobs before state jobs) was already in
  place from Slice 08; this slice adds the missing-parent failure guard that
  makes the scheduling contract enforceable.
- No frontend files or later-slice frozen/provenance contracts were added.
  `generated_request_link` / `provenance_link` remain `None` placeholders.
