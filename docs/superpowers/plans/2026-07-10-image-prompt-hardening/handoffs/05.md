## Contract delivered

### CompiledGenerationRequest

`compiled_request.compile_generation_request(...)` is the one pure
provider-independent compiler. It combines the prepared canonical prompt IR
(`ImagePrompt`) with the finalized Slice 04 `ReferencePlan`, the selected style
text/spec, the route profile, and explicit generation controls into one typed,
immutable, frozen-dataclass request. No file discovery, LLM call, persistence,
or provider call occurs inside it.

`COMPILED_REQUEST_SCHEMA_VERSION = 1`.

#### Compiled-request schema

`CompiledGenerationRequest` carries:

- `schema_version` (`COMPILED_REQUEST_SCHEMA_VERSION`).
- `asset_kind` (`panel | character_ref | location_plate | prop_ref | style_sample`)
  and `asset_identity` (e.g. `scene_001:panel_001`).
- Route/model identity — three DISTINCT fields, never collapsed:
  - `requested_alias` (the effective model string / gateway alias),
  - `expected_route` (`ImageRoute` enum),
  - `configured_provider_model` (the provider model string from
    `describe_image_model`).
  - There is NO `actual_provider_model` field — observed execution identity
    belongs to result provenance after transport (Slice 11).
- Style: `selected_style_text` + `selected_style_source_hash` (None unless a
  source hash is supplied).
- `sections`: tuple of `CompiledPromptSection(kind, title, lines)` in a fixed
  order (see below).
- `final_prompt`: the concatenation of section bodies.
- `protected_anchors`: tuple of `ProtectedAnchor(kind, entity_id, name,
  appearance_state_id, text)` projected from character identities + location/
  prop anchors.
- `reference_plan`: the finalized Slice 04 `ReferencePlan` (unchanged).
- `reference_instructions`: tuple of `CompiledReferenceInstruction` (one per
  selected reference, final order, semantic — see rules below).
- `requested_shape` + `effective_dimensions` from `panel_aspect`.
- `controls`: `GenerationControls(negative_prompt, seed, guidance_scale,
  steps_override)` — all default None (Slice 06 verifies support).
- `prompt_source_sha256` (carried forward unchanged from the prompt).
- `reference_selection_fingerprint` (the Slice 04 selection fingerprint).
- `compiled_request_sha256` (see hash projection below).
- `warnings` (carried forward from the plan; non-blocking).

#### Canonical serialization (prompt-section order)

`_build_sections` emits sections in one stable order:

1. `protected_anchors` — character identity + location/prop anchors, verbatim
   (`.strip()` only, never `_clean`/`_shorten`).
2. `scene_direction` — composition, setting, lighting, mood, key props, key
   objects, visual requirements, continuity, visual brief / distilled brief.
3. `style` — the selected style text.
4. `reference_instructions` — one semantic instruction per selected reference.
5. `system_constraints` — generated from typed fields via
   `generation_prompt.generate_system_constraints`.
6. `user_addenda` — the editable `constraints` field.
7. `geometry` — output dimensions + shape + controls.

`final_prompt` joins every section body with blank lines.

#### Reference-instruction rules (role-aware, facet-precise)

`compile_reference_instruction(asset, index)` compiles one
`CompiledReferenceInstruction` per selected `ReferenceAsset`. The instruction
uses a provider-independent positional marker (`Reference {index}`), never a
Reve `<img>N</img>` tag. Slice 07 serializes the marker.

By authority scope and role:

- **subject / FULL_APPEARANCE** — "identity reference for {label} — match
  {preserve facets}; do not copy its pose or background". Preserve facets
  cover face, hair, build, wardrobe, anatomy (every facet the plan preserved).
- **subject / IDENTITY_ONLY** — "identity reference for {label} — preserve
  only {face, hair, build}; ignore {wardrobe, anatomy} that conflict with the
  active appearance state; do not copy its pose or background".
- **location_plate (no state)** — "location reference for {label} — preserve
  architecture, landmarks and materials".
- **location_plate (active state)** — "location reference for {label} —
  preserve architecture, landmarks and materials that the active state does
  not replace; the active damage, weather, or time-of-day anchor wins over any
  conflicting canonical features".
- **prop** — "object reference for {label} — preserve object; ignore reference
  backdrop".
- **style** — "style reference for {label} — preserve medium, mark-making and
  palette; ignore depicted content".
- **continuity** — "visual continuity reference — ignore facets incompatible
  with current states".

The generic "Use reference images for identity, palette, and continuity only —
do not copy their borders, layout grids, backgrounds, or framing." guard is
DELETED. Each instruction names its exact preserved/ignored facets instead.

#### Configured route/model fields

Three distinct fields, never collapsed: `requested_alias` (alias),
`expected_route` (`ImageRoute` enum), `configured_provider_model` (provider
model string). No `actual_provider_model` field — actual execution identity is
result provenance (Slice 11).

#### Compiled hash projection

`compiled_request_sha256` is a deterministic SHA-256 over:

`schema_version, asset_kind, asset_identity, requested_alias, expected_route,
configured_provider_model, selected_style_text, selected_style_source_hash,
final_prompt, protected_anchors[], reference_selection_fingerprint,
requested_shape, effective_dimensions, controls`.

It EXCLUDES diagnostics (`reference_plan.dropped`, `warnings`) and timestamps.
Therefore:

- Changing a selected reference's bytes changes the hash (via the selection
  fingerprint, which covers selected content hashes).
- Changing an unselected diagnostic candidate does NOT change the hash.
- Changing warnings/dropped-candidate diagnostics alone does NOT change the
  hash.
- A generation-time style change changes the hash (style text/source hash are
  in the projection) while `prompt_source_sha256` (Slice 03's stored source
  hash, which excludes style) is carried forward unchanged.

#### Active-state validation

`_validate_active_state_authority` raises `CompiledRequestError` before any
prompt is built when a FULL_APPEARANCE base-look ref (no recorded state) is
selected for a subject the prompt places in a locked, visually-significant
state. This is a compiler-level backstop for a plan bug; the per-reference
instructions make active-state authority explicit (identity-only ignores
wardrobe/anatomy; location-state anchors win over canonical facets).

### Draw-path integration

`s7_draw.py` `_generate_panel` and `estimate_panel_image_cost_usd` compile a
`CompiledGenerationRequest` from the prompt + the Slice 04 `ReferencePlan` +
the route profile + the configured provider model, then pass
`compiled.reference_instructions` to `render_generation_prompt(...,
reference_instructions=...)`. The renderer serializes the compiled
instructions into the provider wire format (Reve `<img>N</img>` for indexed
routes, plain semantic instructions for non-indexed routes) without
re-selecting references or re-capping. A direct `render_generation_prompt`
call without a compiled request falls back to the legacy provider-tagged block
from the `refs` list (used by tests and Labs).

## Behavior and deliberate deviations

- The compiler is additive: it does not change `IMAGE_PROMPT_VERSION` (still
  23) and does not alter the stored `ImagePrompt` model. The compiled request
  is a generation-time projection consumed by the draw/estimate paths.
- `render_generation_prompt` keeps its legacy `refs=` fallback for direct
  callers (tests, Labs). The brief permits not migrating all callers; provider
  adapters are untouched. Slice 07 migrates provider serialization.
- `GenerationControls` is empty/default until Slice 06 verifies per-route
  control support. The hash already covers control intent so adding a verified
  control later changes identity correctly.
- No paid/model calls were made.
