# Scenewright visual showcase audit

Audit date: 2026-09-14. Real local project: **The Call of Cthulhu**, H. P. Lovecraft. This is a shot-selection audit, not a final marketing edit.

## Recommendation

Lead with the finished comic, reveal the decisions behind it, and return to the comic. **Page 40 in the reader**, **page 40 beside its approved references**, and **the oil/stained-glass style comparison** are the strongest three shots. Together they explain the payoff, continuity, and artistic direction without asking viewers to read a dashboard.

The interface already has an editorial identity: paper-colored work surfaces, heavy ink typography, red registration-like accents, reference sheets, and numbered stations. Preserve that character. Use close framing of the actual work rather than adding generic dashboard graphics.

Review the [contact sheet](audit-captures/contact-sheet.png). Numbered PNGs in [audit-captures](audit-captures/) are the candidate captures; filenames match the shot IDs below. UI captures are 2560 × 1440, with no browser chrome. Capture 28 is a 2400px-tall render of the existing PDF page. These are review candidates; a final website crop should be selected for its intended placement.

## Best website screenshot set

Use these **ten**, in this order. They tell the story without making a visitor study every stage.

1. **21 — Finished comic hero.** Caption direction: “Your story, on the page.” Keep the monster's scale and both panels; use the empty reader surround for layout space if useful.
2. **26 — Inspectable continuity.** “See the references behind every page.” Crop to the review modal while retaining its tabs and reference labels.
3. **09 — Style comparison.** “One scene. Different visual directions.” Retain both proof titles; use the real comparison region as the crop.
4. **12 — Character direction.** “Direct the cast, down to the details.” Include anchor and reference views with the artwork.
5. **14 — Location plates.** “Build a world your pages return to.” Keep the section heading and at least three complete plates.
6. **23 — Saved reference versions.** “Revisit an individual reference.” Keep current image and previous-version thumbnails together; don't describe thumbnail clicks as previews.
7. **05 — Story promises.** “An adaptation with a brief you can shape.” Prioritize promises, tone, and Edit controls rather than the whole long form.
8. **02 — Complete page gallery.** “Review the book, page by page.” Keep progress count, page thumbnails, and review affordances.
9. **04 — Page correction workspace.** “A finished page is still fixable.” Include existing art and “What would you like to change?”; no invented successful correction.

10. **19 — Saved PDF ready.** “Take your book with you.” Retain the real Download PDF link and edition checks.

**11 — Cast gallery** is an alternate if reference imagery is more valuable than an export screenshot. For a six-image site, keep 21, 26, 09, 12, 05, and 04.

## Proposed 42-second storyboard

The film opens with a brief result, goes back through its production decisions, and ends with the full comic payoff. No generation waits or fabricated progress animation.

| Time | Picture and action | Message | Capture/composition |
|---|---|---|---|
| 0–3s | Close on page 40's reveal, easing out just enough to reveal panel borders. | “Your story. A finished comic.” | **Still 21**, reframed and animated in Remotion later. |
| 3–7s | Story promises → short cut to the numbered extracted scenes. | “Start with the story.” | **Stills 05 + 06**, controlled crops; avoids unreadable full-screen scrolling. |
| 7–12s | Compare oil painting and stained glass versions of the same audition. | “Direct the look.” | **Live Playwright**: choose the two Compare controls, reveal comparison; hold the real result. |
| 12–17s | Open Wilcox's reference, then its saved febrile appearance. | “Keep the cast recognizable—even as the story changes.” | **Live Playwright**, read-only modal opening. No regenerated assets. |
| 17–21s | Location plate → current location and previous-version thumbnails. | “Inspect and revisit each piece.” | **Stills 14 + 23** with a short reframing move. Avoid clicking Restore. |
| 21–25s | One adapted beat's lettering → planned page with staging/rhythm. | “Shape the words. Plan the page.” | **Stills 17 + 18**; use labels/crops, not a fast scroll through raw notes. |
| 25–30s | Gallery → open page 1 → open Make changes. | “Correct a page without starting over.” | **Live Playwright**, stop at the empty request workspace. This shows the scope of correction, not completed regeneration. |
| 30–35s | Page 40's Visual review tab, showing sailor, city, and creature beside the page. | “Keep every decision inspectable.” | **Live tab switch**, then hold **26**. Do not click Check the artwork or imply verification. |
| 35–40s | Reader page 40 → page 41, then return to the strongest reveal. | Finished comic takes over the frame. | **Live Playwright page navigation**, then **still 21** for a clean final hold. |
| 40–42s | Hold artwork; add Scenewright wordmark and concise end line. | “From prose to pages—with you in the director's chair.” | Remotion typography later; no composition work started in this audit. |

A 20-second cut can use: payoff (2s), brief (3s), style comparison (4s), reference/page comparison (4s), correction workspace (3s), finished page/end mark (4s). The 42-second version better earns the inspectable-production-chain claim.

| Page before/after render comparison | Code supports it when a previous successful render exists. All active comic renders observed here are revision 1; multiple request files are not proof of multiple successful renders. Do not fabricate it. |
| Mark a correction region | The current `RevisionDraft`/`AnnotationEditor` supports marks after adding a correction request. Not exercised: no resettable editing fixture is authorized, and this audit stays read-only. A future browser-only draft can be considered separately without copying the project. |
| Drag lettering or SFX | Not an exposed editing operation in this current full-page pipeline. Do not storyboard a compose editor or movable generated lettering. |

## UI cleanup worth considering before final capture

These are proposals only; no application source was changed for the audit.

| Priority | Finding | Small, useful change |
|---|---|---|
| High | Style header shows “Generate and approve the character reference… before creating this cover,” although the production already has references and pages. It dominates the artwork in red. | Investigate the cover prerequisite/status calculation and scope any warning to its relevant action. Do not merely hide a genuine blocker in a marketing screenshot. |
| High | A single matching library card is dwarfed by empty space; long documents also stay narrow at 2560px. | Use intentional crops for the website; consider a focused project overview or a responsive max-width adjustment separately. No need for a showcase-specific fake library. |
| High | Adaptation and Plan lead with long optional editorial diagnostics, including identifiers such as `beat_0017`. | Collapse the notes behind a summary, foreground narrative treatment/book rhythm, and translate internal IDs into readable page/beat labels. Keep the underlying evidence inspectable. |
| Medium | “Complete” in Library and “Done” in Book were initially visible before saved export checks were available, and coexist with unresolved optional page findings. | Separate production completion, optional review state, and export readiness in the labels. Do not mark unreviewed artwork verified. |
| Medium | Visual review says “optional paid” while its action displays `~0 credits`. | Inspect estimate readiness/rounding; present a clear loaded estimate or unavailable state. Do not advertise the review as free based on this screen. |
| Medium | Reference anchors include prompt-like prefixes such as `1man`; cards can truncate long descriptions. | Add a readable presentation summary while preserving the authoritative anchor verbatim in its inspectable detail. |
| Medium | Reference-version thumbnails immediately restore on click. | A preview-before-restore affordance would make history safer to explore and a stronger motion demonstration. Existing behavior is documented, not changed. |
| Low | Reader uses a generic “READING” label; the title is absent and the bottom of the underlying shell can remain visible. | Include the book title and check full-screen modal coverage. Final artwork crop can avoid the exposed shell. |

Visual hierarchy is strongest when artwork leads and controls support it (reader, style comparison, reference modals). Text-heavy artifacts work better as evidence than hero images. Small text and thumbnail labels will not remain readable at mobile website sizes; deliver purposeful crops or separate detail shots. This is a showcase critique, **not** a WCAG compliance audit; contrast ratios and keyboard coverage were not comprehensively tested.

## Running the app and repeating capture

Repository layout: Python/FastAPI backend in `novel_to_comic/src/novel_to_comic/`, React/Vite frontend in `web/`, real data in `projects/`, existing isolated Remotion scaffold in `showcase/video/` (untouched). Current backend and frontend were already running and were reused. The backend process was verified to use the repository's `projects` directory.

If they are stopped, run these separately from the repository root, using the existing local environment configuration:

```sh
novel_to_comic/.venv/bin/pipeline serve --dev --projects-dir projects
```

```sh
cd web
npm run dev -- --host 127.0.0.1
```

Frontend: `http://127.0.0.1:5173`; backend: `http://127.0.0.1:8000`. Vite proxies `/api` and `/static` to the backend. No model gateway needs to be started merely to inspect saved artifacts. Do not start or rerun pipeline stages to record this demo.

Use the existing signed-in Playwright CLI session `showcase`, or open one and sign in with the authorized local test account through the login UI. Credentials are deliberately absent from scripts and this document; no reusable authenticated state file is delivered.

```sh
npx --no-install playwright-cli -s=showcase open http://127.0.0.1:5173/login
# Sign in before capture. Do not include the login screen in recordings.
node showcase/scripts/capture-audit.mjs
node showcase/scripts/contact-sheet.mjs
```

Individual groups can be rerun, for example:

```sh
node showcase/scripts/capture-audit.mjs styles
node showcase/scripts/capture-audit.mjs cast pages
node showcase/scripts/capture-audit.mjs planning reader
```

The optional artwork-only PDF render (28) is recreated from the existing package with Poppler; it does not rebuild the PDF:

```sh
pdftoppm -f 40 -l 40 -singlefile -scale-to 2400 -png \
  projects/947150d4-7d2f-4726-a018-5539f933ea56/the-call-of-cthulhu/exports/comic.pdf \
  showcase/audit-captures/28-exported-page40
node showcase/scripts/contact-sheet.mjs
```

Dependencies: installed root Playwright CLI, the frontend's `sharp` package for the contact sheet, and Poppler for optional PDF rendering. No Remotion dependency is involved in this audit.

The runner uses Playwright CLI, accessible role/name selectors, fixed 2560 × 1440 framing, explicit page/query context, deterministic scroll targets, reduced motion, hidden carets, and font/visible-image readiness checks. It rejects non-GET/HEAD/OPTIONS `/api` requests, including automatic telemetry and preflight writes. It never clicks generation, restore, approval, or saving controls. The guard is browser-side capture protection, not an application authorization mechanism.

Only account-menu and credit-balance chrome is hidden at screenshot time for privacy; no artifact, warning, result, or review status is rewritten. The library is filtered through its real search control. Screenshot-time privacy styling is isolated in `showcase/scripts/capture-audit.mjs`. No application demo mode or data copy was introduced.

The reader group expects the now-existing PDF and current preflight; it fails clearly if these disappear. The runner hashes project files before/after its work and writes `audit-captures/capture-verification.json`. It fails if source content changes during capture, including concurrent changes by another process. Pixel output is expected to change when the UI/assets change; this setup makes navigation and framing repeatable rather than promising identical pixels across arbitrary application versions. It intentionally stops on missing labels/artifacts instead of silently substituting mock results.

## Verification and limits

- The first Book visit had no saved preflight and its automatic POST was blocked. Later in the session a saved PDF/preflight became available (file timestamp 15:23 local). This audit did not issue an export request. Final candidates reflect that later state; repeatability checks cover the project state at capture time, not external activity across the entire session.
- All major user-facing production areas above were opened in the authenticated local application using the original project.
- No project copy, new production version, asset regeneration, restore, approval, correction submission, or export creation was performed by this audit.
- Repeat captures include a SHA-256 integrity comparison of the original project's files; see the generated verification record for the last run.
- Contact-sheet QA caught transient blank artwork/reference frames in an early replay. The final runner explicitly waits for the expected artwork and reference images to load/decode before saving, in addition to general visible-image readiness.
- Account details, credentials, developer paths, and unrelated library titles are excluded from the delivered screenshots. Raw Playwright snapshots/logs remain outside the deliverable in the ignored `.playwright-cli` directory.
- Current successful page renders are revision 1; saved cast/location history is real. A failed or repeated provider request is not a before/after comic revision.
- OCR findings establish only text-review evidence. No visual-review generation was run and no artwork is represented as newly verified.
- The only code added is the showcase capture/contact-sheet tooling. Existing unrelated checkout edits and `showcase/video/` were left alone.
- Final video recording, Remotion composition, audio, final website crops, and encoded-video validation are intentionally pending shot/storyboard review.
