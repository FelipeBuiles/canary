## Conclusions

- **Measured.** Inflow stopped. Signups were 7 in the week of 2026-09-28, then 0 for the next three weeks and one day. Weekly pageview people fell from 134 to single digits and low teens.
- **Measured.** No outside account reached a first page. Of 7 mature accounts, 3 created a project, 1 picked a style, and 0 reached `page_ready` within 14 days. No export and no purchase has ever been recorded.
- **Inference.** The credit wall is the likeliest stop. No signup credit grant appears in canary's server code (searched 2026-10-27, `billing.py` and the server package), so a new author must buy before pages are drawn. One person hit `credit_blocked`, one started checkout, and none bought. These events were not joined to the cohort, so this is not proven to be the same person.
- **Alternative explanations.** Missing or late events, identity stitching across the email-confirmation hop, account backfill that only happens on a return visit, or authors who simply stopped. None is ruled out.
- **Measured.** Search is not a channel yet: 27 impressions in 28 days. GA4 shows no search, social, or referral sessions.

## Caveats

- Internal-marker coverage is incomplete. One person who is not marked internal viewed `/backoffice` in window W. Team members may be inside the "external" counts.
- The PostHog person-property mode (event-time or query-time) was not returned by `project-get`, so it is unknown.
- `export_download_requested` and `credits_purchased` have never been received in this project. A real export or purchase that failed to send its event would look identical to none. Check Stripe and the billing ledger by hand before trusting the zero for purchases.
- Accounts are backfilled only on return visits, so the cohort can miss accounts that never came back.

## Queries (verbatim)

Query 1: `call project-get {"id":630262} --json`. Only id, name, timezone, and organization were read. The project token was not printed.

Query 2, coverage by environment:

```sql
SELECT event, coalesce(toString(properties.environment), '(none)') AS env, count() AS event_rows, uniqExact(person_id) AS people
FROM events
WHERE timestamp >= toDateTime('2026-09-29 00:00:00') AND timestamp < toDateTime('2026-10-27 00:00:00')
  AND coalesce(person.properties.$internal_or_test_user, false) = false
  AND event IN ('$pageview','signup_submitted','account_created','project_created','style_selected','page_ready','export_download_requested','credit_blocked','checkout_started','checkout_cancelled','credits_purchased','refund_completed','account_observed')
GROUP BY event, env ORDER BY event, env LIMIT 100
```

Query 3: the "ordered, mature activation cohort" SQL from `.agents/skills/growth-analytics/SKILL.md`, with `now()` frozen to `toDateTime('2026-10-27 00:00:00')`.

Query 4: the "new accounts by first-touch source" SQL from the same skill, with the same frozen anchor.

Query 5, pageviews by canonical path:

```sql
SELECT coalesce(toString(properties.$pathname), '(none)') AS path, count() AS views, uniqExact(person_id) AS people
FROM events WHERE event = '$pageview' AND timestamp >= toDateTime('2026-10-27 00:00:00') - INTERVAL 28 DAY AND timestamp < toDateTime('2026-10-27 00:00:00') AND properties.environment = 'production' AND coalesce(person.properties.$internal_or_test_user, false) = false
GROUP BY path ORDER BY people DESC LIMIT 25
```

Query 6, previous window P: the event list from query 2 without `account_observed` and `refund_completed`, grouped by event, from `- INTERVAL 56 DAY` to `- INTERVAL 28 DAY`, with both filters.

Query 7, weekly:

```sql
SELECT toStartOfWeek(timestamp, 1) AS week_monday, event, count() AS event_rows, uniqExact(person_id) AS people
FROM events WHERE timestamp >= toDateTime('2026-10-27 00:00:00') - INTERVAL 28 DAY AND timestamp < toDateTime('2026-10-27 00:00:00')
  AND properties.environment = 'production' AND coalesce(person.properties.$internal_or_test_user, false) = false
  AND event IN ('$pageview','signup_submitted','account_created','project_created')
GROUP BY week_monday, event ORDER BY week_monday, event LIMIT 100
```

Query 8, production by internal flag (aggregate only):

```sql
SELECT if(coalesce(person.properties.$internal_or_test_user, false), 'internal_or_test', 'not_marked_internal') AS who, event, count() AS event_rows, uniqExact(person_id) AS people
FROM events WHERE timestamp >= toDateTime('2026-10-27 00:00:00') - INTERVAL 56 DAY AND timestamp < toDateTime('2026-10-27 00:00:00') AND properties.environment = 'production'
  AND event IN ('account_created','project_created','style_selected','page_ready','export_download_requested','checkout_started','credits_purchased')
GROUP BY who, event ORDER BY who, event LIMIT 100
```
